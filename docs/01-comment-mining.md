# 01 · 评论挖掘

> 数据：`data/comments_raw.csv`（原始）→ `data/comments_tagged.csv`（打标后）。目标 100–150 条。

## 采集方式

- 关键词：`@点点 多推`、`点点 推荐这种`、`点点 这类`……（实际用过的关键词记在这里）
- 覆盖的笔记类型：AI 前沿解读 / 书籍分享 / 工具教程 / 其他
- 采集时间范围：
- 排除规则：（例如：明显是营销号互动、与 AI 内容无关的笔记）

## 标签体系

157 条已打标，写在 `data/comments_tagged.csv`。一条可以有多个标签，用顿号分隔，写在前面的是主要诉求。

| 标签 | 定义 | 示例 |
|---|---|---|
| 总结提炼 | 把当前笔记、视频或评论区讲清楚 | "总结一下" |
| 订阅推送 | 希望以后持续推同类，或按固定时间推 | "每天早上10点发给我" |
| 要原文 | 要逐字稿、字幕、文案、图中文字或 prompt 原文 | "生成本视频的逐字稿" |
| 概念解释 | 不懂某个概念，或要确认自己的理解 | "MCP是什么" |
| 核对评价 | 辨真伪、要判断、给观点，或代答题主 | "这个博主说的对不对" |
| 场景用法 | 按自己的身份、任务或目标，要可执行用法 | "大学生如何更好地利用这个平台" |
| 抽取清单 | 把书名、信息源、时间线等条目列出来 | "视频提到的书都有哪些" |
| 账号操作 | 关注、关闭推送、蹲后续、更新提醒，或单次再推 | "关闭订阅每天十点的推送" |
| 要链接 | 要文章、出处或笔记链接 | "链接发个我" |
| 求对比 | 比较几个概念、产品或方案 | "和 pi 比较" |
| 意图不清 | 看不出在要什么 | "x j zj q" |

## 结果

### 高赞评论在要什么

点赞 Top 3 全部是**订阅推送**，而且描述得非常具体：

| 赞 | 诉求 | 原话 |
|---|---|---|
| 47 | 订阅推送 | "帮我定期搜集类似博主这种前沿性的 AI 领域知识和 AI 工具技巧，最好和科研相关，梳理好框架和核心内容 3-5 条，每……" |
| 19 | 订阅推送 | "帮我定期搜集类似博主这种前沿性的 AI 领域知识和 AI 工具技巧，梳理好框架和核心内容 3-5 条，每天早上 10 点……" |
| 9 | 订阅推送、总结提炼、要原文 | "该博主每次更新之后，对内容进行分点总结后在晚上八点发给我，梳理清晰的框架和逐字稿内容" |
| 4 | 总结提炼 | "整理视频概要 通俗易懂分点列出" |
| 3 | 核对评价、要链接 | "检查这些观点是否真的来自 Cat Wu，并列出出处" |
| 3 | 要链接 | "harness 实践部分，参考的 openai 和 anthropic 哪两个文章，链接发个我" |

频次最高的诉求（总结提炼）平均只有 0–3 赞；频次第二的诉求（订阅推送）拿走了几乎全部高赞。**总结是"我现在就要"的个人动作，订阅是"大家都想要"的公共诉求**——别人看到会点赞，说明这条评论替他们说了话。

而且高赞评论已经把产品规格写出来了：定期 / 同类博主 / 前沿 AI + 工具技巧 / 梳理框架 / 3–5 条 / 固定时间推送。

## 结论

- **H1 不成立（按频次）**：最大诉求是总结提炼（41%），不是求同类推荐（19%）。但**按点赞加权 H1 成立**：高赞几乎全是订阅推送。两者不矛盾——总结是私人即时需求，订阅是群体需求。
- **意外发现 1**：用户已经把产品规格说出来了（定期、同类、3–5 条、固定时间、梳理框架）。方案阶段直接拿这个当需求文档。
- **意外发现 2**：出现了"核对评价"和"要链接"（合计 13 条）——**可信度和溯源是真实诉求**，和 00 里"信源分级"的假设对上了。
- **意外发现 3**：书籍分享类笔记下的诉求是"抽取清单"，和 AI 前沿解读下的诉求不是一回事，**后面只做 AI 前沿，不做书籍**。
- **对访谈的影响**：问题不该是"你需不需要一个聚合产品"，而是（a）"你现在怎么跟 AI 进展，上次漏掉什么"（验证信源分散），（b）"你看完一条解读之后会做什么"（验证总结 vs 订阅），（c）"你怎么判断一条 AI 解读靠不靠谱"（验证溯源诉求）。
